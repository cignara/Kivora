1. Design Brief
This brief defines the visual identity, tone, and experience goals for Kivora. Every design decision should be measured against this document before moving to production.

1.1  Platform Identity
Platform nameKivoraTaglineWhere Kids Love to Learn & PlayMascotKivi the Fox — friendly, curious, energetic guideTarget usersChildren aged 2–11 (primary); Parents & Teachers (secondary)Tone of voiceWarm, playful, encouraging — never condescending or pressuringEmotional goalA child should feel excited, safe, and proud when using Kivora
1.2  Visual Tone
Kivora sits between the soft warmth of Duolingo and the structured clarity of Khan Academy Kids. It should feel adventurous but never chaotic. Think: theme park map, not a cluttered toy store.

Reference benchmarks
PlatformBorrowAvoidDuolingo KidsWarm palette, reward loopsStreak anxiety, loss framingKhan Academy KidsStructured layout, clear hierarchyFlat, corporate feelStarfallAudio-first simplicity for toddlersDated visual stylePBS KidsCharacter-led warmth, safe feelOverly cluttered home screen

1.5  Animation & Motion Rules
• All page transitions: fade-up (0.6s ease-out)
• Cards: translateY(-6px) + scale(1.02) on hover, 0.25s
• Mascot Kivi: float animation (translateY 0 ? -12px, 3s loop)
• Reward unlock: wiggle + shimmer + scale burst
• Progress bars: fill with 1.2s ease transition on mount
• ADHD focus mode: all non-essential animations disabled
• Toddler tier: no sudden audio or animation surprises — all motion is triggered by child interaction only

1.6  Accessibility Baseline
• WCAG 2.1 AA minimum for all public and parent/teacher pages
• WCAG 2.1 AAA target for child portal (critical path screens)
• Minimum touch target: 44×44px (48×48px for toddler tier)
• All text must pass 4.5:1 contrast ratio on its background
• Dyslexia font toggle must be available on all child-facing text
• Audio read-aloud on all child-facing text (not optional)
• No timed interactions without a “More Time” override for ADHD/Dyslexia profiles

5. Responsive Breakpoint Strategy
Kivora is mobile-first. The majority of child users will be on tablets and phones. Design for the smallest supported screen first.

BreakpointWidthPrimary DeviceKey Layout Rulesxs (base)< 480pxPhones (portrait)1-column; large tap targets; hamburger nav; stacked CTAssm480–767pxPhones (landscape) / small tablet1–2 col grid; condensed cardsmd768–1023pxTablets (portrait)2–3 col grid; sidebar begins; nav expandslg1024–1279pxTablets (landscape) / small laptop3–4 col grid; full nav; sidebar fixedxl1280px+DesktopMax-width container (1280px); full layout
Toddler Mode exception:
Toddler tier (ages 2–3) must be designed exclusively for tablet (md breakpoint) as primary canvas. Phones are not recommended for this age group due to fine motor limitations. Design touch targets at 64×64px minimum.

7. Designer Handoff Checklist
Before submitting any screen for developer handoff, confirm all items below are complete.

Design Quality
• All required states designed (default, hover, active, disabled, loading, error, empty)
• All breakpoints covered (xs, sm, md, lg, xl)
• Colour contrast passes 4.5:1 on all text
• Touch targets minimum 44×44px (64px for toddler screens)
• Fonts loaded from Google Fonts CDN (Baloo 2 + Nunito)
• All icons from a single consistent icon set (specify which set)

Component Usage
• No one-off components — all UI uses the component inventory in Section 4
• No hardcoded colours — all colours from the brand token palette in Section 1.3
• Kivi mascot used consistently (no redraws; use provided asset files only)

Content & Copy
• No lorem ipsum on any screen submitted for review
• All child-facing text at Grade 1–2 reading level maximum (Flesch-Kincaid check)
• Error messages and empty states written in human, friendly language
• No countdown timers, scarcity text, or FOMO mechanics anywhere in child portal

Accessibility
• Focus states visible on all interactive elements
• Alt text defined for all images and illustrations
• Form fields have visible labels (no placeholder-only labels)
• Dyslexia font and high-contrast mode variants noted in spec

Developer Handoff
• Redlines/measurements annotated or auto-inspect enabled
• All asset exports named in kebab-case (e.g., kivi-fox-wave.svg)
• Responsive behaviour annotated per component
• Animation specs noted (duration, easing, trigger) per animated element
